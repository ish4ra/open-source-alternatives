## What makes the list

A project should be meaningfully open source, useful enough to recommend, and a credible alternative within its category. The goal is not to list every project that exists.

See [`CRITERIA.md`](CRITERIA.md) for the selection rules and [`CONTRIBUTING.md`](CONTRIBUTING.md) for contributions.

## Labels used in the guides

- **Self-hosted** — can be run on your own server or device.
- **Hosted option** — an official or third-party hosted service is available.
- **Local-first** — designed to keep primary data on your own devices.
- **Federated** — can communicate across independently operated servers.
- **Cross-platform** — available on several major desktop/mobile platforms.

## Philosophy

Prefer a few strong choices over a huge stale catalog. When a project dies, changes license, becomes effectively abandoned, or stops being a good recommendation, it should be removed or clearly marked.

> Open source does not automatically mean private, secure, free-of-cost, or better for every person. Pick tools based on your actual requirements and threat model.
