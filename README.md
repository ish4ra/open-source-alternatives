## 🚀 Quick picks

| If you want to replace… | Start with | Why |
|---|---|---|
| Chrome / proprietary browsers | **Firefox, LibreWolf, Helium, Cromite** | Multiple engines and privacy trade-offs |
| WhatsApp / Telegram-style private messaging | **Signal, Element + Matrix** | Simple centralized secure messaging vs federated open messaging |
| Google Authenticator / Authy | **Ente Auth, Aegis** | Open-source 2FA with sync or local-first options |
| Google Drive / cloud sync | **Nextcloud, Seafile, Syncthing** | Self-hosted cloud or direct device sync |
| Google Photos | **Immich, PhotoPrism** | Self-hosted photo libraries |
| Plex-style media server | **Jellyfin** | Fully open-source personal media server |
| Discord / team chat | **Matrix + Element, Zulip, Mattermost** | Federated or self-hosted communication |
| Notion / notes | **Joplin, Logseq, Memos** | Local-first or self-hosted knowledge tools |
| Photoshop / Illustrator | **GIMP, Krita, Inkscape** | Mature creative tools |
| GitHub-hosted workflows | **Forgejo, Gitea** | Self-hosted Git forges |
| Cloud AI frontends | **Ollama + Open WebUI / LocalAI** | Local/self-hosted AI stack |

> **Tip:** the “best” alternative depends on what you value most: privacy, compatibility, self-hosting, polish, platform support, or simplicity.

## 💬 Signal or Element + Matrix?

They both belong on an open-source alternatives list, but they solve the problem with different network models.

| Pick | Model | Best for |
|---|---|---|
| **Signal** | Centralized service with open-source client/server code | Simple private chats, groups and calls |
| **Element + Matrix** | Federated protocol/network with server choice and self-hosting options | Federation, communities, interoperability and server control |

**Matrix is the protocol/network; Element is a client.** See **[secure messaging](categories/secure-messaging.md)** for the fuller comparison.

## 💎 Hidden gems worth noticing

The main directory covers strong alternatives. **[HIDDEN-GEMS.md](HIDDEN-GEMS.md)** is for projects that are easier to miss.

A few examples:

| Project | Why it is interesting |
|---|---|
| **Helium** | Fast Chromium-based browser with a privacy-focused approach; promising but still a younger project |
| **Ente Auth** | End-to-end encrypted 2FA with cross-device sync |
| **PairDrop** | Browser-based local file transfer with almost zero setup |
| **Rnote** | Polished handwritten notes / sketching app |
| **Karakeep** | Save and archive links, notes and web content |
| **Yamtrack** | Self-hosted tracking for movies, TV, anime, games and books |
| **Ampcast** | Unified music UI across sources such as Navidrome and Jellyfin |
| **Gatus** | Lightweight config-as-code uptime/status monitoring |

Hidden-gem status is **not** a security endorsement. Younger projects are marked with maturity caveats where appropriate.

## 🏷️ Labels used across the repo

| Label | Meaning |
|---|---|
| **Self-hosted** | You can run it on your own server/device |
| **Hosted option** | Official or third-party hosted service exists |
| **Local-first** | Primary data is designed to stay on your own devices |
| **Federated** | Independent servers can interoperate |
| **Cross-platform** | Available on several major desktop/mobile platforms |
| **Beta / young project** | Promising, but maturity and update history deserve extra scrutiny |

## 🧠 How projects are selected

This repo intentionally prefers a **shorter high-signal list** over a giant catalogue.

A project should have:

- a meaningful open-source codebase;
- a real use case, not just novelty value;
- enough project health to be worth recommending;
- a clear reason someone might choose it over a proprietary alternative;
- honest caveats when the project is young, niche, difficult to deploy, or platform-limited.

Projects can also be removed when they become abandoned, change direction/licensing, or stop being a good recommendation.

Read the full policy: **[CRITERIA.md](CRITERIA.md)**.

> Open source does **not** automatically mean private, secure, free-of-cost, or better for every person. Evaluate the project that fits your actual requirements.
